# LumoLM

An **experimental, from-scratch byte-level GPT** implemented in PyTorch. It includes a causal Transformer, UTF-8 byte tokenizer (vocabulary of 256), local training, resumable checkpoints, text generation, unit tests, and a CPU CI smoke test.

**Current status:** Code and a very small example corpus are provided. The example can verify the full training/inference path, but it **cannot** train an assistant or useful large language model. Training a capable LLM needs much more carefully licensed data, compute and evaluation. No pretrained weights are bundled.

## Quick start

Python 3.10+ is recommended. Install PyTorch appropriate for your machine (CUDA, MPS, or CPU), then:

```bash
python -m pip install -r requirements.txt
python -m lumolm.train --data data/demo.txt --checkpoint checkpoints/demo.pt --device cpu --steps 20 --batch-size 4 --block-size 32 --n-layer 2 --n-head 2 --n-embd 64 --eval-interval 10 --eval-iters 2
python -m lumolm.generate --checkpoint checkpoints/demo.pt --prompt 'Question:' --max-new-tokens 80 --temperature 0.8
```

For a fast end-to-end check:

```bash
python -m lumolm.train --data data/demo.txt --checkpoint checkpoints/smoke.pt --device cpu --steps 2 --batch-size 2 --block-size 16 --n-layer 1 --n-head 2 --n-embd 32 --eval-iters 1 --eval-interval 1
python -m lumolm.generate --checkpoint checkpoints/smoke.pt --prompt 'Hello' --max-new-tokens 12 --temperature 0
python -m pytest -q
```

## Incremental inference (KV cache)

Generation now reuses attention keys and values within each context window, avoiding
recomputing the entire prefix for each generated byte. The public `GPT.forward`
return type stays `(logits, loss)` by default; `use_cache=True` additionally
returns per-layer key/value tensors. Use `--no-kv-cache` to compare against the
original full-context inference path:

```bash
python -m lumolm.generate --checkpoint checkpoints/demo.pt --prompt 'Hello' --max-new-tokens 80 --no-kv-cache
```

**Context rollover:** This model uses learned absolute position embeddings.
Once the context reaches `block_size`, the cache is rebuilt from the last
`block_size` bytes so generation matches the uncached sliding-window behavior.
That makes long-form generation slower than a true rolling-position cache, but
avoids silently changing model predictions. The cache helps most before rollover.
No pretrained or 270M-parameter model weights are provided by this change.

## Talk to a checkpoint (experimental)

You can inspect **actual generated bytes** rather than mistaking a successful
training smoke test for conversational intelligence. With a **trained** checkpoint:

```bash
python -m lumolm.chat --checkpoint checkpoints/demo.pt --question "What is LumoLM?" --device cpu
python -m lumolm.chat --checkpoint checkpoints/demo.pt --device cpu
```

Chat uses the sample corpus' `Question: ...\\nAnswer:` framing, maintains a short
conversation history, and stops generating at the first newline instead of
continuing into the next simulated user turn. The default `data/demo.txt` is just 944 bytes, so a checkpoint trained on it can
only imitate its handful of examples. An additional, **synthetic and repetitive**
bilingual `data/dialogue_demo.txt` corpus is included for reproducible dialogue
experiments. It demonstrates learning/memorization, NOT broad generalization.
CI intentionally probes questions absent from that dataset too.
The terminal interface cannot make it knowledgeable or reliable. For reproducible
probes run `PYTHONPATH=. python scripts/probe_chat.py --checkpoint checkpoints/demo.pt`.

### Why the old toy chat gives incorrect answers

The legacy `lumolm_chat_cli.py` in earlier downloadable demo bundles
loads a **synthetic FAQ checkpoint**, typically the ~372K-parameter
6,000-step model. It is not the newer TinyStories checkpoint and cannot be
converted into one by renaming its `probe.pt` file. The toy model regularly
returns incorrect arithmetic (`1+1 -> 11`, etc.), meaningless filler when
prompted with punctuation, and repeated memorized answers. **These are model
quality limitations**, not fixed by installing a Python package, changing
sampling, or hardcoding arithmetic answers.

The maintained launcher is now also available by its earlier filename:

```bash
# From a cloned LumoLM repository with a compatible toy checkpoint:
python3 -m pip install -U numpy   # only needed to silence PyTorch's NumPy warning
python3 lumolm_chat_cli.py --checkpoint checkpoints/probe.pt --show-context
# Equivalent package interface:
python3 -m lumolm.chat --checkpoint checkpoints/probe.pt --show-context
```

`--show-context` reports how many earlier turns fit in the tiny 128-byte
context window. The CLI now builds and bounds the prompt **before** inference;
overlong questions raise a clear error instead of silently discarding question
bytes. With this model, long multi-turn chat remains impractical.
For story continuation use `python -m lumolm.generate --checkpoint
checkpoints/story.pt --prompt "Once upon a time"`; TinyStories weights
are **not** trained for Question/Answer chat.

## Expanded corpus and real evaluation

The earlier small dialogue test set contains only about 18 KB of repeated
examples. The new **deterministic, original/synthetic** and category-balanced dataset generator covers
English and Traditional Chinese, basic computer knowledge, Minecraft,
greetings and arithmetic (addition, subtraction and multiplication). It writes
independent training and validation files. **Arithmetic operand pairs are held
out by group** (including synonymous phrasings and equivalent operand order),
so the held-out score is more meaningful than testing solely memorized
training phrases. It is still a narrow synthetic evaluation, not a general
language-understanding benchmark.

```bash
python scripts/build_corpus.py
python -m lumolm.train --data data/expanded_train.txt --val-data data/expanded_val.txt \
  --checkpoint checkpoints/expanded.pt --device auto --steps 6000 \
  --batch-size 8 --block-size 128 --n-layer 3 --n-head 4 --n-embd 96 \
  --lr 0.0007 --eval-interval 1200 --eval-iters 8
PYTHONPATH=. python scripts/evaluate_math.py --checkpoint checkpoints/expanded.pt \
  --train data/expanded_train.txt --val data/expanded_val.txt --samples 24
python -m lumolm.chat --checkpoint checkpoints/expanded.pt --device auto
```

The evaluation prints **actual** model completions, exact-match accuracy on
seen synthetic arithmetic, unseen operand combinations, and out-of-domain
questions. Low or zero accuracy is a real limitation, not a test failure.
Do not claim the model can reason merely because training loss falls. The
checkpoint is a from-scratch ~0.36M-parameter experiment, **not Lumo-270M**.
Training data/validation hashes are recorded to prevent accidental resume
on changed source content. Generated datasets and checkpoints are ignored by Git.

## Train your own model

Use a sufficiently large, UTF-8 **plain text** corpus you have permission to use. By default, training/validation are split contiguously (last 10% used for validation). To avoid data leakage, prefer **a separate held-out validation corpus** using `--val-data` and ensure examples/topics do not overlap. Do not add secrets or private data to your corpus. Example:

```bash
python -m lumolm.train --data /path/to/your-corpus.txt --checkpoint checkpoints/experiment.pt --device auto --steps 10000 --batch-size 16 --block-size 128 --n-layer 4 --n-head 4 --n-embd 128 --eval-interval 500 --eval-iters 20
```

To resume (the **same corpus** and existing checkpoint are required; `--steps` is the total target number of optimizer updates):

```bash
python -m lumolm.train --data /path/to/your-corpus.txt --checkpoint checkpoints/experiment.pt --resume --steps 15000
```

`--device auto` prefers CUDA, then Apple MPS, then CPU. For CPU training, start with a small model. Use `--grad-accum N` to accumulate gradients over N mini-batches. Output checkpoints are saved atomically at evaluation intervals and at the end; they include model, optimizer, training step, RNG state, model configuration, and corpus SHA-256. Checkpoints and private datasets are git-ignored. Load **only trusted** checkpoints.

## Optional larger text source: TinyStories

The bundled bilingual FAQ/math data is small, repetitive and intended for
tests. For a genuine next-token language-model experiment, LumoLM has a
**bounded** import path for the separately licensed
[TinyStories dataset](https://huggingface.co/datasets/roneneldan/TinyStories).
TinyStories is published under `cdla-sharing-1.0`; review the upstream terms
and retain attribution before using or redistributing it. No TinyStories text
or pretrained weights are committed to this repository.

```bash
python scripts/sample_tinystories.py --max-train-bytes 8388608 --max-val-bytes 524288
python -m lumolm.train --data data/tinystories_sample/train.txt \
  --val-data data/tinystories_sample/validation.txt \
  --checkpoint checkpoints/story.pt --device auto \
  --steps 3000 --batch-size 8 --block-size 128 \
  --n-layer 2 --n-head 2 --n-embd 64 --eval-interval 500
python -m lumolm.generate --checkpoint checkpoints/story.pt \
  --prompt "Once upon a time" --max-new-tokens 120 --temperature 0.8
```

The sampler reads only a capped prefix of two **separate upstream splits**
to avoid mixing training and validation text and writes `SOURCE.json` with
download URLs, source/license details, sizes and SHA-256 hashes. The sampled
files are git-ignored and are not redistributed by CI. GitHub Actions runs a
small, explicitly limited story experiment to test this end-to-end path. It
does not benchmark instruction following or create a competent assistant.

## Limitations / next steps

- Byte-level GPT is easy to inspect but less efficient than a learned subword tokenizer for large-scale training. It may produce malformed UTF-8; inference decodes malformed sequences with replacement characters.
- No instruction tuning, chat template, large-scale dataset streaming, multi-GPU training or distributed checkpointing yet.
- GitHub Actions runs a tiny **CPU smoke test**, not large-scale GPU training; there is no claim that training is running continuously in the cloud.
- Larger models require a proper tokenizer, evaluation benchmark, dataset pipeline and hardware plan before claiming useful LLM quality.

## Train in GitHub Actions (CPU)

Open **Actions → Train LumoLM (manual CPU) → Run workflow**. Enter the path to a committed UTF-8 corpus and 1–2000 optimizer steps. The job uploads a downloadable `lumolm-cpu-checkpoint` artifact for 14 days. Extract `manual.pt` and run inference locally using `python -m lumolm.generate --checkpoint manual.pt --prompt 'Hello'`. GitHub-hosted CPU runners are only suitable for tiny experiments. Training is **not** automatically scheduled, and Actions jobs finish after each run.
